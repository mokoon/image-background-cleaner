## 1. 목표 (Goal)

이미지에서 **캐릭터와 배경을 분리**하여, **캐릭터만 남은 투명 배경 PNG(RGBA)** 를 만든다.

- 입력 이미지는 배경이 제각각이다: **흰색 / 파란색 / 녹색 크로마키 / 검은색** 등.
- 캐릭터 주변에 **물체가 있을 수도, 없을 수도** 있다.
- 대상은 주로 **애니메이션풍 캐릭터 일러스트**(Stable Diffusion 생성물)다.
- **어떤 분리 방식이 가장 깔끔한지 눈으로 비교**하는 것이 이 프로그램의 핵심 목적이다. 따라서 한 방식만 쓰지 않고 **여러 방식을 동시에 돌려 결과를 나란히 보여준다.**

### 성공 기준 (검증 가능한 형태)
1. 웹 GUI에서 이미지 1장을 업로드하면, 5가지 방식(A~E)의 투명 PNG 결과가 **나란히** 표시된다.
2. 각 결과는 **실제 알파 채널을 가진 유효한 RGBA PNG**다 (알파값이 0~255로 분포하고, 전부 255(불투명)가 아님).
3. 각 결과를 **개별 다운로드**할 수 있다.
4. 흰/파랑/녹색/검정 배경 테스트 이미지 각각에서, 최소 한 방식(isnet-anime)은 배경이 투명 처리된다.

### 방식 A — 딥러닝 배경 제거: `rembg` + `isnet-anime` ⭐주력
- `rembg` 라이브러리의 **`isnet-anime` 모델**(애니 캐릭터 전용 학습)을 사용한다.
- 배경색과 무관하게 캐릭터를 통째로 분리하며, 주변 물체가 있어도 캐릭터만 인식한다.
- **알파 매팅(alpha matting)** 옵션을 토글로 제공한다(머리카락 경계를 부드럽게; 느려짐).
- 참고: 비교용으로 일반 `u2net` 모델도 선택 가능하게 하되, 기본값은 `isnet-anime`.

```python
from rembg import remove, new_session
session = new_session("isnet-anime")
result_rgba = remove(input_pil, session=session, alpha_matting=alpha_matting)
```
- 모델 가중치는 첫 실행 시 자동 다운로드된다(수십~수백MB). 네트워크가 필요함을 README에 명시.

### 방식 B — 색상 기반 크로마키 (OpenCV / NumPy)
- 배경이 **균일한 단색**일 때 픽셀 단위로 가장 깨끗하다.
- 절차:
  1. 이미지 **네 모서리 영역을 샘플링**해 배경색을 자동 추정(중앙값).
  2. **LAB 또는 HSV 색공간에서 색 거리** 기준으로 배경 마스크 생성. (RGB 유클리드보다 지각적으로 안정적)
  3. 임계값(threshold)은 **슬라이더로 조절** 가능하게 한다.
  4. 마스크 경계를 살짝 **feather(가우시안 블러) / erode**로 다듬어 계단 현상을 줄인다.
  5. (선택) 녹색/파란색 크로마키의 **spill suppression**(경계 색 번짐 제거)을 옵션으로.
- 한계(의도된 동작): 캐릭터 안에 배경색과 같은 색이 있으면 그 부분이 뚫린다. 이는 비교의 관찰 포인트이므로 억지로 막지 않는다.

### 방식 C — GrabCut (OpenCV, 반자동)
- 모델 가중치 없이 그래프컷으로 전경/배경 분리.
- 절차:
  1. 초기 사각형 = 이미지 가장자리에서 안쪽으로 일정 비율(예: 5%) 들어간 영역을 **probable foreground**로 지정.
  2. `cv2.grabCut(..., mode=cv2.GC_INIT_WITH_RECT)`를 수 회 반복(iteration은 슬라이더).
  3. 최종 마스크로 알파 생성.
- 한계: 애니 일러스트에선 isnet-anime보다 경계가 지저분할 수 있음. 비교 대상으로 포함.

### 방식 D — SAM (Segment Anything, Meta)
- 새 의존성 없이 **rembg 내장 SAM ONNX(vit_b)** 사용 (`new_session("sam")`, 첫 실행 시 가중치 자동 다운로드).
- 프롬프트 자동 지정: **중앙 = 전경 점, 네 모서리 = 배경 점**. 박스 프롬프트(가장자리 5% 안쪽)는 합성 테스트에서 배경을 통째로 선택해서 제외.
- 한계: 결과는 이진 마스크(부드러운 경계 없음). 클릭 없이 점 1개로는 캐릭터의 일부(얼굴 등)만 잡을 수 있음.

### 방식 E — 알파 매팅 (pymatting closed-form)
- trimap 기준 마스크 = isnet-anime 마스크. 경계 안팎 `band` px를 미지 영역으로 두고 `estimate_alpha_cf` + `estimate_foreground_ml`(색 번짐 제거).
- 기준 마스크에 확실한 전경/배경이 없으면 매팅 없이 기준 마스크를 그대로 사용(에러 방지).

### 추가 기능 — 테두리 강조 (2026-09-15, 사용자 요청, `outline_tool.py`)
- 위치: 레이어 편집기 아래 별도 섹션. 버튼 2개: `레이어 편집기 현재 이미지 가져오기`(편집기 화면 합성 canvas를 그대로 복사, 선택 표시 제외) / `외부 이미지 가져오기`(파일 선택).
- 인식: 알파 ≥ 임계값(1~255, 기본 128) = 그림, 미만 = 투명 배경.
- 테두리: 그림 **바깥쪽** 투명 픽셀 중 그림까지 유클리드 거리 ≤ 두께+0.5인 픽셀을 테두리 색으로 채움(+0.5는 1px에서도 대각선이 끊기지 않게). 임계값 미만의 옅은 원본 픽셀은 테두리 색 위에 겹쳐 가장자리가 자연스럽게 이어짐.
- 설정: 색상(기본 검정, color picker), 두께(기본 1px, 슬라이더 1~50 + 숫자 입력 최대 500), 임계값(슬라이더 + 숫자). 변경 시 미리보기 즉시 갱신.
- 구현(가정/결정): 편집기 canvas를 읽어야 하므로 **브라우저에서 처리**(서버 왕복 없음). 거리 필드는 Felzenszwalb-Huttenlocher 정확 EDT(O(n)), 임계값이 바뀔 때만 재계산하고 색·두께 변경은 칠하기만 다시 함.
- 한계: 이미지 가장자리에 닿은 부분의 테두리는 캔버스 밖이라 잘림(캔버스 확장은 미구현). 투명 부분이 없거나 그림 픽셀이 없으면 안내 문구 표시.
- **추가(사용자 요청) — 원본 레이어**: `레이어 편집기 현재 이미지 가져오기`로 가져온 경우, 원본 이미지를 테두리 결과 **아래**에 깔고 불투명도(0~100%, 가져올 때마다 0%로 시작) 조절. 외부 이미지는 원본이 없어 조절 줄 숨김.
  - 원본 레이어는 표시용: 테두리 인식은 가져온 편집 이미지의 알파로만 계산. 원본 불투명도 변경은 합성만 다시 함(테두리 재계산 없음).
  - 저장 = 화면에 보이는 그대로(원본 0%면 테두리 결과만) — 편집기와 동일한 규칙.
- **변경(사용자 요청) — 편집 레이어 선택지**: A / B / **A+B** / 원본 / 일괄 순서. A+B = 지우개·복원·선택 영역 지우기/복원·선택 레이어 초기화를 A와 B에 동시 적용(원본 레이어는 그대로, 일괄과의 차이). 되돌리기는 A·B 함께 1단계. 선택 시 안내 문구 표시.
- **추가(사용자 요청) — 원본 블러 (레이어 편집기 + 테두리 강조)**: 원본 레이어에 가우시안 블러(0~50 슬라이더, 숫자 입력 최대 100px), 값 변경 즉시 반영.
  - 적용 범위(결정): 원본 전체가 아니라 **누끼 모양 밖만 블러**. 누끼 모양이 있는 곳은 선명한 원본을 그 알파만큼 겹침 → 원본을 위에 두든 아래에 두든 캐릭터는 선명, 경계 번짐(후광) 방지. 누끼 모양 = 편집기에선 A·B 편집 레이어의 합(표시 불투명도와 무관), 테두리 강조에선 가져온 편집 이미지.
  - 구현: canvas `ctx.filter = blur(Npx)`(GPU). 가장자리 1px 줄을 3σ만큼 늘려 붙인 뒤 블러해 이미지 테두리가 투명하게 번지지 않게 함. 블러 결과는 반경별 캐시. 두 컴포넌트가 독립 스크립트라 `blurImage` 함수는 양쪽에 중복.
  - 편집기: 블러 조작도 되돌리기 대상(슬라이더 한 번 = 1단계), 새 이미지 시 0으로 초기화. 테두리 강조: 가져올 때마다 0으로 초기화. 저장 = 보이는 그대로(블러 포함).
  - 한계: `ctx.filter`를 지원하지 않는 브라우저(일부 구형 Safari)에서는 블러가 적용되지 않음.
  - 원본 전달(결정): 편집기 원본은 JS 클로저 안에 있어 외부에서 못 읽음 → 편집기가 숨김 `canvas.orig-copy`(기존 마법봉 샘플용 canvas를 DOM으로 옮김)에 원본을 그려두고, 테두리 강조가 가져올 때 복사.

## 10. 실행 방법 (완성 후 목표)

> **추가(2026-09-15, 사용자 요청) — 기본 다크 테마**: `app.py`의 `DARK_JS`(페이지 로드 스크립트, `launch(js=DARK_JS + HELP_JS)`).
> - Gradio 6.13 프론트엔드의 테마 결정: (내부값) → URL `?__theme=` → 없으면 `system`(OS 따라감, OS 변경 시 재적용). dark/light면 `body`에 `dark` 클래스를 한 번 붙이거나 뗌. 설정 창은 URL `__theme`를 바꾸고 새로고침.
> - 구현(결정): URL에 `__theme`가 없으면 `history.replaceState`로 `__theme=dark`를 붙이고(새로고침 없음) `body.dark` 적용, Gradio가 system 모드로 클래스를 떼면 MutationObserver로 다시 붙임. `__theme=light` 등 명시값이 있으면 건드리지 않음.
> - 수정(검증 중 발견): OS가 라이트일 때 `gradio-app` 영역은 다크인데 **`body` 배경만 흰색**(Gradio `index.html`의 `body { background: var(--bg) }` + `@media (prefers-color-scheme: dark)` 규칙이 `.dark` 클래스와 무관하게 OS만 따라감 → 콘텐츠 밖 여백/아래가 흰색). 앱 CSS에 `body.dark { background: var(--body-background-fill); }` 추가(선택자 우선순위로 덮어씀). 순정 Gradio에서 `?__theme=dark`를 라이트 OS에서 써도 같은 현상.
> - 한계: 설정 창에서 "system"을 고르면 Gradio가 `__theme`를 지우고 새로고침 → 다시 다크 기본값이 적용됨(라이트는 선택 가능). `launch(head=...)`는 index.html에 서버측 삽입 자리가 없어(클라이언트에서 늦게 삽입될 가능성) 사용하지 않음.
>
> **추가(2026-09-15, 사용자 요청) — `실행.bat` 런처**: 더블클릭 → `python app.py --inbrowser` 실행, 서버 준비 후 Gradio `inbrowser`로 http://127.0.0.1:7860 자동 열기. `app.py`는 `server_name="127.0.0.1", server_port=7860` 고정(다른 포트로 넘어가지 않음), 브라우저 자동 열기는 `--inbrowser` 인자일 때만(개발 중 `python app.py`는 안 열림).
> - 7860이 이미 LISTENING이면 새로 띄우지 않고 페이지만 엶 / `python` 없음·패키지 없음(gradio, rembg, cv2 import 실패) → 안내 후 pause / 앱이 에러로 끝나면 pause.
> - .bat 내부 문구는 ASCII(영문): .bat 안의 비ASCII 문자는 cmd 줄 해석을 깨뜨릴 수 있어서. `chcp 65001` + `PYTHONIOENCODING=utf-8`로 앱 로그 한글 출력.
